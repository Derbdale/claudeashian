- **Sonnet 5 code-review harnesses: prompt for coverage, filter downstream** — Sonnet 5 follows "only report high-severity" instructions more literally than Sonnet 4.6, so recall can drop even though bug-finding ability rose. Anthropic's recommended fix: "Report every issue you find, including uncertain or low-severity. Do not filter for importance at this stage — a separate verification step will do that. Include a confidence level and estimated severity so a downstream filter can rank them." (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5)
- **Sonnet 5 → Sonnet 4.6 effort mapping** — When migrating and benchmarking: Sonnet 5 at `medium` is roughly comparable to Sonnet 4.6 at `high`, and Sonnet 5 at `high` is roughly comparable to Sonnet 4.6 at `max`. Match by observed thinking length rather than the effort-parameter name to compare like-for-like. (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5)
- **Break Sonnet 5's default design house-style: ask for 4 directions first** — On open-ended frontend briefs Sonnet 5 settles into a consistent default palette. Vague redirects ("don't use that colour", "make it minimal") just shift it to a different fixed default. Instead: "Before building, propose 4 distinct visual directions (bg hex / accent hex / typeface + a one-line rationale). Ask the user to pick one, then implement only that direction." (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5)
- **On Sonnet 5 with `thinking: disabled`, add an explicit tool nudge** — Sonnet 5 is more agentic than Sonnet 4.6 by default, but with thinking turned off it becomes noticeably less likely to reach for tools or consider searching. If you rely on tool calls in a thinking-off pipeline, add a system-prompt instruction explicitly naming why and how each tool should be used, or bump effort to `high`/`xhigh` where tool usage rises substantially. (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5)
- **`/compact` before you step away — the prompt cache expires after an hour** — Summarising the session while the cache is still warm is much cheaper than doing it cold when you come back. Run `/compact` before any break longer than a few tens of minutes so the summarisation itself reuses cached tokens. (Source: https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions)
- **Set model and effort at session start; changing mid-session busts the cache** — Model choice and effort level become part of the cached prefix; switching either mid-conversation invalidates the cache and forces the whole conversation to be re-encoded on the next turn. Pick both up front and stay on them for the life of the session. (Source: https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions)
- **Quiet noisy command output — large tool outputs stay in context for the whole session** — Anything Claude sees once persists in the conversation buffer until you `/compact` or `/clear`, so verbose build logs or test output are paid for on every subsequent turn. Add `--quiet`, redirect to a file Claude can grep on demand, or push the noisy command into a subagent. (Source: https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions)
