# Current Discoveries

New items discovered since the last newsletter.

- **`enforceAvailableModels` managed setting** — When enabled, the `availableModels` allowlist also constrains the Default model (a Default that would resolve to a disallowed model falls back to the first allowed model), and user or project settings can no longer widen a managed `availableModels` list. Useful for organisations enforcing model governance across workspaces (v2.1.175, June 12, 2026). (Source: https://code.claude.com/docs/en/changelog)
- **Claude Fable 5 generally available in GitHub Copilot** — Claude Fable 5 is available in GitHub Copilot on Pro+, Max, Business, and Enterprise plans via the model picker in VS Code, Visual Studio, GitHub.com, JetBrains, Xcode, and other supported surfaces. Fable 5 requires 30-day data retention for Anthropic's safety classifiers; Copilot Business and Enterprise admins must explicitly enable the policy (it's off by default). In internal benchmarks, Fable 5 completed equivalent work with fewer tool calls and lower token consumption than previous Opus-tier models. (Source: https://github.blog/changelog/2026-06-09-claude-fable-5-is-generally-available-for-github-copilot/)
- **Anthropic donates MCP to the Linux Foundation's Agentic AI Foundation** — Announced December 9, 2025, Anthropic donated the Model Context Protocol to the Agentic AI Foundation (AAIF), a directed fund under the Linux Foundation co-founded by Anthropic, Block, and OpenAI. MCP joins Block's goose and OpenAI's AGENTS.md as founding projects. The governance transfer makes MCP an open, vendor-neutral standard maintained by the community. By March 2026, monthly SDK installs had reached 97 million and the official registry crossed 800 servers. (Source: https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation)
- **Fable 5 effort calibration: `high` by default, `xhigh` for hardest tasks** — Use `high` as the default effort for most Claude Fable 5 tasks; reserve `xhigh` for the most capability-sensitive workloads. Lower effort settings on Fable 5 still often exceed `xhigh` performance on prior models, so drop to `medium` or `low` for routine or latency-sensitive work. (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5)
- **Ground Fable 5 progress claims against tool results** — For long autonomous runs, instruct Fable 5 to audit each progress claim against an actual tool result from the session. Anthropic found this nearly eliminated fabricated status reports on tasks designed to elicit them: "Before reporting progress, audit each claim against a tool result from this session." (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5)
- **Don't ask Fable 5 to reproduce its reasoning** — Prompts or skills that instruct Claude Fable 5 to echo, transcribe, or show its internal reasoning as response text can trigger the `reasoning_extraction` refusal category, causing elevated fallbacks to Opus 4.8. Audit existing CLAUDE.md files and skills for show-your-thinking instructions when migrating. Use adaptive thinking `display: "summarized"` if you need reasoning visibility. (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5)
