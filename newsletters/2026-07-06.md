# Current Discoveries

New items discovered since the last newsletter.

- **Subagents run in background by default** — Subagents launched by Claude Code now run in the background by default, keeping the main session interactive while the subagent works. Subagents surface permission prompts to the main session interface rather than blocking or auto-denying silently (v2.1.198, July 1, 2026). (Source: https://github.com/anthropics/claude-code/releases)
- **Claude Code v2.1.201: Sonnet 5 mid-conversation system role fix** — Claude Sonnet 5 sessions no longer use the mid-conversation system role for harness reminders, eliminating a source of unexpected context disruption in long Sonnet 5 sessions (v2.1.201, July 4, 2026). (Source: https://releasebot.io/updates/anthropic/claude-code)
- **MCP tunnels management API moved to Claude API** — The MCP tunnels endpoint migrated from `/v1/organizations/tunnels` on the Admin API to `/v1/tunnels` on the Claude API, under the `anthropic-beta: mcp-tunnels-2026-06-22` header and `workspace:manage_tunnels` WIF scope. The previous Admin API surface stays available during a migration window (June 22, 2026). (Source: https://platform.claude.com/docs/en/release-notes/api)
- **`claude --continue` and `claude --resume` session flags** — `claude --continue` picks up the most recent session without prompts; `claude --resume` opens an interactive picker to choose from all saved sessions by name. Use `/rename` to give sessions descriptive names (e.g. `oauth-migration`) so they're easy to find later. (Source: https://code.claude.com/docs/en/best-practices)
- **`Ctrl+G` opens plan in text editor during plan mode** — In plan mode, press `Ctrl+G` to open the current plan draft in your configured text editor for direct annotation and editing before Claude proceeds with implementation. (Source: https://code.claude.com/docs/en/best-practices)
- **Writer/Reviewer pattern for quality improvement** — Open two parallel sessions: Session A implements the feature; Session B reviews the diff in a fresh context, unbiased because it didn't write the code. Example: "Review the rate limiter implementation in @src/middleware/rateLimiter.ts. Look for edge cases, race conditions, and consistency with existing middleware patterns." After review, pass findings back to Session A to address. Also useful for tests: Session A writes tests, Session B writes code to pass them. (Source: https://code.claude.com/docs/en/best-practices)
