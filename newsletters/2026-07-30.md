# Current Discoveries

New items discovered since the last newsletter.

- **Fast mode for Claude Opus 5** — Fast mode is available for Claude Opus 5 at approximately 2.5× the standard output speed, priced at $10/$50 per million input/output tokens (double the standard Opus 5 rate of $5/$25). Became available when Opus 4.7 fast mode was removed on July 24, 2026; Opus 4.8 fast mode also continues. (Source: https://releasebot.io/updates/anthropic/claude-code)
- **`/subtask` command** — Launches an in-session subagent for a focused sub-task while keeping the main conversation active. Introduced in v2.1.212 (July 17, 2026) as the replacement for the previous in-session subagent command; `/fork` was simultaneously repurposed to duplicate the full current conversation into a background session. (Source: https://releasebot.io/updates/anthropic/claude-code)
- **`claude auto-mode reset`** — CLI command that restores the default auto-mode configuration, undoing any manual customisations without editing settings files (v2.1.212, July 17, 2026). (Source: https://releasebot.io/updates/anthropic/claude-code)
- **Prompt caching anti-patterns: timestamps and user-specific content break the prefix** — Two common causes of near-100% cache miss rates: (1) including a live timestamp (e.g., "Current time: 2026-07-30T14:32:15Z") in the system prompt — truncate to the day or move it out of the cached prefix entirely; (2) placing user-identifying strings ("You are helping {user.name}") inside the cached system prefix — every user gets a unique prefix and a cache miss. Move per-user context to the `user` message instead. (Source: https://medium.com/@ai_transfer_lab/claude-api-prompt-caching-isnt-broken-your-cache-prefix-probably-is-1ba738c42023)
- **Monitor cache_read_input_tokens to verify caching health** — In a well-configured cache, `cache_read_input_tokens` should dominate usage while `cache_creation_input_tokens` should be near zero after the first request. If creation tokens remain high across requests, a broken cache prefix (timestamps, per-user content, or whitespace inconsistencies from your prompt builder) is causing repeated cache misses. Cache reads are priced at 10% of base input cost, so healthy caching can cut input token costs by 60–90%. (Source: https://www.aimagicx.com/blog/prompt-caching-claude-api-cost-optimization-2026)
