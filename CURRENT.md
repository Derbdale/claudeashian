# Current Discoveries

New items discovered since the last newsletter.

- **Claude Sonnet 5 real-time cybersecurity safeguards** — Claude Sonnet 5 is the first Sonnet-tier model with real-time cybersecurity safety classifiers. Requests involving prohibited or high-risk cybersecurity topics may be refused mid-generation, returning `stop_reason: "refusal"` on an HTTP 200 response — not an error. Refused requests that produce no output are not billed. (Source: https://platform.claude.com/docs/en/about-claude/models/whats-new-sonnet-5)
- **Claude apps gateway for Amazon Bedrock and Google Cloud** — Self-hosted control plane for Claude Code on Amazon Bedrock and Google Cloud, providing corporate SSO (Google Workspace, Entra ID, Okta), centrally enforced managed settings, per-user cost attribution, OTLP telemetry, and daily/weekly/monthly spend limits at org, group, or user level. Runs as a stateless container on Linux backed by PostgreSQL; does not send inference traffic to Anthropic unless explicitly configured. Announced June 29, 2026. (Source: https://claude.com/blog/introducing-the-claude-apps-gateway)
- **Three breaking API changes when migrating to Claude Sonnet 5** — (1) Adaptive thinking is on by default; disable with `thinking: {type: "disabled"}` and revisit `max_tokens` since thinking tokens now count toward it. (2) Manual extended thinking (`thinking: {type: "enabled", budget_tokens: N}`) is removed — returns a 400 error; use adaptive thinking with the `effort` parameter instead. (3) Setting `temperature`, `top_p`, or `top_k` to non-default values returns a 400 error — remove them when migrating. Also: Sonnet 5 uses a new tokenizer producing ~30% more tokens than Sonnet 4.6 for the same text, so recount token budgets and expect higher per-request costs even though per-token pricing is unchanged. (Source: https://platform.claude.com/docs/en/about-claude/models/whats-new-sonnet-5)
