# Tips & Tricks

Tips, tricks, context management advice, and prompt techniques for Claude and Claude Code.

- **Context degrades at 60% fill** — Claude's output quality starts degrading at 20-40% of the context window due to attention mechanism weighting. Monitor the status bar fill indicator and compact or start a new session at 60%. (Source: https://institute.sfeir.com/en/claude-code/claude-code-context-management/tips/)
- **Use targeted grep over full file reads** — A targeted search consumes ~200 tokens vs ~3,000 for a full file read. Prefer grep/search over reading entire files. (Source: https://codeagents.app/guides/context-management)
- **Keep CLAUDE.md under 100 lines** — CLAUDE.md loads at the start of every conversation (~800 tokens). Move specific instructions into separate .claude/ files that load on demand. (Source: https://institute.sfeir.com/en/claude-code/claude-code-context-management/tips/)
- **Use thinking keywords for deeper reasoning** — Words like "think", "think hard", "think harder", or "ultrathink" directly impact how much thinking budget is allocated to Claude. (Source: https://www.datacamp.com/tutorial/claude-code-best-practices)
- **Double-escape to fork sessions** — Press Esc+Esc to jump back to earlier points in your conversation and fork Claude Code sessions to reuse well-formed context windows. (Source: https://blog.sshh.io/p/how-i-use-every-claude-code-feature)
- **Include tests for self-checking** — Including tests, screenshots, or expected outputs so Claude can check itself is the single highest-leverage thing you can do. (Source: https://www.datacamp.com/tutorial/claude-code-best-practices)
- **Opus 4.6 effort defaults and ultrathink** — Opus 4.6 defaults to medium effort on Max/Team plans. Use "ultrathink" keyword to trigger high effort for maximum reasoning depth (v2.1.68). (Source: https://code.claude.com/docs/en/changelog)
- **Context engineering over prompt engineering** — In 2026, how you structure context matters more than how you phrase prompts. Use structured sections: INSTRUCTIONS, CONTEXT, TASK, OUTPUT FORMAT. A well-structured system prompt ("contract" format with role, success criteria, constraints, output spec) outperforms clever wording. (Source: https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- **Front-load critical information** — Place the most important instructions in the first 10% and last 10% of your prompt. Claude's attention mechanisms weight these sections more heavily than the middle. (Source: https://www.aiforanything.io/blog/claude-prompt-engineering-context-engineering-guide-2026)
- **Context rot degrades recall before the limit** — Even before hitting the hard context limit, Claude's ability to accurately recall earlier information decreases as token count grows (the "context rot" effect). Compact or start fresh proactively, not reactively. (Source: https://context.engineering)
- **Use /compact within a task, /clear between tasks** — `/compact` summarises conversation history while staying on the same task; use `/clear` when switching to a completely different task to avoid cross-task context contamination. (Source: https://code.claude.com/docs/en/whats-new)
- **Rewind menu to compress earlier context** — In the Rewind menu, select "Summarize up to here" to compress older context while keeping recent turns intact, without resetting the whole session (Week 20, v2.1.139). (Source: https://code.claude.com/docs/en/whats-new)
- **Use an initializer + coding agent pattern for multi-session agents** — For long-running agents spanning multiple context windows, have a dedicated initializer agent create feature lists, progress files, and structured git commits on the first run; subsequent coding agents resume from those artifacts rather than starting cold. (Source: https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- **Tool descriptions are as important as prompts** — For agent-facing tools, the description field significantly impacts performance; treat it with the same care as your system prompt. Use clear namespacing (e.g. `asana_projects_search`), return only relevant data, and implement pagination with sensible defaults — token savings can reach two-thirds compared to verbose responses. (Source: https://www.anthropic.com/engineering/writing-tools-for-agents)
- **`CLAUDE_CODE_NO_FLICKER=1` for smooth streaming** — Set this env var to enable the fullscreen TUI renderer, eliminating terminal flicker during streaming and keeping syntax highlighting stable. Add it to your shell profile for a permanently smoother experience. (Source: https://aiproductivity.ai/guides/claude-code-tips-tricks/)
- **Fable 5 effort calibration: `high` by default, `xhigh` for hardest tasks** — Use `high` as the default effort for most Claude Fable 5 tasks; reserve `xhigh` for the most capability-sensitive workloads. Lower effort settings on Fable 5 still often exceed `xhigh` performance on prior models, so drop to `medium` or `low` for routine or latency-sensitive work. (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5)
- **Ground Fable 5 progress claims against tool results** — For long autonomous runs, instruct Fable 5 to audit each progress claim against an actual tool result from the session. Anthropic found this nearly eliminated fabricated status reports on tasks designed to elicit them: "Before reporting progress, audit each claim against a tool result from this session." (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5)
- **Don't ask Fable 5 to reproduce its reasoning** — Prompts or skills that instruct Claude Fable 5 to echo, transcribe, or show its internal reasoning as response text can trigger the `reasoning_extraction` refusal category, causing elevated fallbacks to Opus 4.8. Audit existing CLAUDE.md files and skills for show-your-thinking instructions when migrating. Use adaptive thinking `display: "summarized"` if you need reasoning visibility. (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5)
- **`CLAUDE_CLIENT_PRESENCE_FILE` suppresses push notifications at your desk** — Set this env var to any file path to tell Claude Code you're present; it won't send mobile push notifications while the file exists. Useful in shell profiles or tmux session startup so pings only reach your phone when you're genuinely away (v2.1.181). (Source: https://github.com/anthropics/claude-code/releases)
- **`@path` syntax references files directly in your prompt** — Type `@src/auth/session.ts` in your prompt to pin a specific file or directory into context, reducing hallucination and grounding responses in your actual code rather than training data. (Source: https://support.claude.com/en/articles/14553413-claude-code-cheatsheet)
- **Use just-in-time context loading for agents** — Rather than pre-loading all relevant data into the system prompt, design agents to retrieve information on demand via tools as they need it. Anthropic's guidance: agents should "dynamically load data via tools rather than pre-loading everything," mirroring human cognition and keeping the context window lean for long-horizon tasks. (Source: https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- **Goldilocks zone for system prompts** — Aim for system prompts that are specific enough to guide behaviour but flexible enough to handle novel situations. Start minimal and add instructions only when you observe failure modes in production; overly detailed system prompts increase token cost and can introduce conflicting constraints. (Source: https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- **`.claude/commands/` is now legacy; migrate to `.claude/skills/<name>/SKILL.md`** — The older `.claude/commands/` directory format for custom slash commands is considered legacy (it still works but is no longer the recommended approach). The current standard is `.claude/skills/<name>/SKILL.md`, which supports richer metadata, parameterised invocation, and marketplace distribution. (Source: https://www.datacamp.com/tutorial/claude-code-slash-commands)
- **Extended thinking blocks are kept in cache prefix on Opus 4.5+ and Sonnet 4.6+** — On Claude Opus 4.5 and above and Claude Sonnet 4.6 and above, prior thinking blocks are kept by default as part of the cached context prefix, enabling efficient multi-turn extended-reasoning sessions. On older models and all Haiku models, thinking blocks are stripped from context after each turn. Changing extended thinking settings (budget, enable/disable) between turns alters the message structure and can break the cache prefix, so avoid toggling settings mid-conversation. (Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- **Three breaking API changes when migrating to Claude Sonnet 5** — (1) Adaptive thinking is on by default; disable with `thinking: {type: "disabled"}` and revisit `max_tokens` since thinking tokens now count toward it. (2) Manual extended thinking (`thinking: {type: "enabled", budget_tokens: N}`) is removed — returns a 400 error; use adaptive thinking with the `effort` parameter instead. (3) Setting `temperature`, `top_p`, or `top_k` to non-default values returns a 400 error — remove them when migrating. Also: Sonnet 5 uses a new tokenizer producing ~30% more tokens than Sonnet 4.6 for the same text, so recount token budgets and expect higher per-request costs even though per-token pricing is unchanged. (Source: https://platform.claude.com/docs/en/about-claude/models/whats-new-sonnet-5)
- **Writer/Reviewer pattern for quality improvement** — Open two parallel sessions: Session A implements the feature; Session B reviews the diff in a fresh context, unbiased because it didn't write the code. Example: "Review the rate limiter implementation in @src/middleware/rateLimiter.ts. Look for edge cases, race conditions, and consistency with existing middleware patterns." After review, pass findings back to Session A to address. Also useful for tests: Session A writes tests, Session B writes code to pass them. (Source: https://code.claude.com/docs/en/best-practices)
